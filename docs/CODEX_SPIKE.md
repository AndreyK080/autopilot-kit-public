# Спайк T15.0: живая проверка привода Codex

Это инструкция для проверки привода `codex` на настоящем Codex (приложение или CLI, вход по ChatGPT, без API-ключей). Результат
записывается в таблицу C1–C8; он нужен, чтобы привод из статуса «написан и покрыт тестами» перешёл в «проверен» (см. [DRIVES.md](DRIVES.md)).

**Подготовка** (один раз, в пустой папке-песочнице; `kit` уже установлен: `python -m kit install`, `python -m kit profile set --drive codex`):

```powershell
git init; python -m kit project init --template generic --path .
python "$HOME\.autopilot-kit\bin\program.py" init --goal "маленькая утилита wc на Python с тестами" --mode semi
python "$HOME\.autopilot-kit\bin\program.py" stage add S1 --title "Ядро wc" --task "функция подсчёта строк, слов и байтов и три теста"
python "$HOME\.autopilot-kit\bin\program.py" start S1
```

Затем откройте **новый чат Codex в этой папке** и вставьте текст ниже целиком.

---

Это спайк T15.0 проекта autopilot-kit (решение D24): проверяем на живом Codex привод программы прогонов Autopilot, который уже написан в `program.py` (команды `codex-run`, `codex-status`, `codex-answer`). Ты работаешь в папке `<папка kit>\spikes\codex-program-demo` — учебный проект со своим git. Ничего не меняй вне этой папки, кроме шага C7 (там указано). API-ключи не используй: только вход ChatGPT этого приложения. Ничего не пушь.

Все факты пиши в `out/CODEX_PROGRAM_SPIKE_RESULTS.md`: таблица «Проверка | Что делал (точная команда) | Факт (вывод, коды выхода, id) | Вывод». Не приукрашивай: если не получилось — так и пиши, с текстом ошибки. Если шаг невозможен — объясни почему и переходи к следующему.

Команда скрипта ниже: `P` = `python "$HOME\.autopilot-kit\bin\program.py"`. В папке уже есть программа: `.autopilot/program.json`, этап S1 начат.

**Подготовка.** Запиши версии: `codex --version` из PATH и бинарника `$env:CODEX_CLI_PATH`; какой из них найдёт скрипт (он берёт `CODEX_CLI_PATH`, иначе `codex` из PATH). Запиши `codex exec --help` и `codex exec resume --help` этого бинарника — нужны флаги песочницы, автоматической проверки запросов (скрипт по умолчанию передаёт `--sandbox workspace-write --approve-for-me`), `--json`, `-o`.

**C1. Запуск этапа.** `P codex-prompt S1` — посмотри задание этапа. Затем `P codex-run S1`. Если запуск или первые события падают из-за флага, которого эта версия не знает, подбери замену по `--help` и запусти `P codex-run S1 --exec-arg <флаг> --exec-arg <значение> …` (замена запоминается для resume). Запиши: команду, которая сработала, pid, и что показал `P codex-status S1` через минуту (`process`, `threadId`).

**C2. Навыки и субагенты в exec.** Проверяй `P codex-status S1` раз в минуту, не дольше 30 минут, пока `process` не станет `exited`. Запиши: вызвались ли навыки `autopilot-roles` и `autopilot` (смотри события в файле из поля `events` прогона в `.autopilot/program.json` → `stages[0].codex.runs`), запускал ли Autopilot субагентов и с какими моделями, появился ли `.autopilot/state.js`.

**C3. Вопрос владельцу.** Когда `process: exited`: в выводе `codex-status` поле `check.verdict` — ожидается `waiting` (`kind: briefing`), а `lastMessage` — сам вопрос этапа. Запиши оба. Если Autopilot не остановился на вопросе — запиши, что произошло.

**C4. Ответ и продолжение.** `P codex-answer S1 "Ответ владельца получен через оркестратора: формат вывода — одна строка, как у wc: 3 12 87 file.txt. Продолжай прогон."` Проверяй `P codex-status S1` раз в 2–3 минуты, не дольше 60 минут. Затем `P check --record`: ожидается `passed` (или `unfinished` — тогда снова `codex-answer` по `lastMessage` и запиши, почему он остановился). Запиши, видны ли эти прогоны в истории приложения Codex.

**C5. Пробуждение по задаче в этом чате.** Создай задачу в этом же чате (thread automation): каждые 10 минут — «выполни `P codex-status S1` и допиши строку с временем и `process` в `out/automation.log`». Дождись одного срабатывания, запиши, пришло ли оно в этот же чат с его контекстом, затем удали задачу. Если создать задачу сам не можешь — запиши, что сказал инструмент. Отдельно: можно ли так же поставить разовую задачу на конкретное время (для продолжения после сброса лимита).

**C6. Разрешения.** Запиши: были ли запросы подтверждения во время C1–C4, повисал ли прогон на них, что сделала автоматическая проверка, какие флаги в итоге нужны.

**C7. Хук Stop.** Kit уже кладёт в проект `.codex/hooks.json` с `gate.py --hook codex-stop` (D33). Проверь: (а) после `kit project init` и подтверждения в `/hooks` хук срабатывает на конце хода; (б) красный гейт возвращает Codex к работе (код 2 + stderr), второй провал подряд при `stop_hook_active` пропускается; (в) в чате с первой репликой `$autopilot-program` хук ничего не проверяет — для этого посмотри, что лежит в `transcript_path` (формат строк `response_item` / `event_msg`, служебные реплики AGENTS.md и окружения до первой настоящей) и сверь с `kit/gate.py` (`_user_text`, `CODEX_CONTEXT_STARTS`); (г) путь с `python "C:/Users/…/gate.py"` в `command` работает в оболочке Codex на Windows или нужен `commandWindows`. Запиши входной JSON хука в `out/hook-input.json` для сверки полей.

**C8. Лимиты и дашборд.** `P limits --phase start --codex` — запиши вывод и сверь с последним `rate_limits` в самом свежем `~\.codex\sessions\**\*.jsonl`. `P page` — запиши адрес; открой его во встроенном браузере Codex, если он есть, и запиши, получилось ли.

В конце — итог одной строкой на каждый пункт C1–C8: «да / нет / частично» и почему, и список флагов `--exec-arg`, если пришлось менять.

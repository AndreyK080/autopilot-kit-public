# Чем autopilot-kit отличается от оригинального Autopilot

**Оригинал** — навык `autopilot` Nick Vels: <https://github.com/nick-vels/skills> (лицензия MIT, © 2026 Nick Vels;
[README](https://github.com/nick-vels/skills/blob/main/README.md), [CHANGELOG](https://github.com/nick-vels/skills/blob/main/CHANGELOG.md)).
Весь процесс разработки — брифинг, спецификация, тикеты, субагенты, ревью, слепая приёмка — придуман и написан автором оригинала.

**Kit не меняет ни одного файла оригинала.** Его копия лежит в этом репозитории в `vendor/autopilot` байт в байт (с лицензией автора
`vendor/LICENSE` и манифестом хешей `vendor/UPSTREAM.json`); установка идёт из неё, без сети. Так репозиторий — полное решение: версия
оригинала и надстройка всегда проверены вместе. Всё остальное в этом репозитории — надстройка рядом. Этот файл показывает, что именно добавлено и чем
отличаются три привода (подробно о приводах — [DRIVES.md](DRIVES.md)).

Состояние на **12.11.2026**: закреплён коммит `5ed4b79`, версия оригинала **2.2.3** (`kit/data/upstream.pin`).

## Что есть в оригинале

| Возможность | Как устроена в оригинале |
|---|---|
| Процесс одного прогона | `/autopilot` ведёт идею через 8 этапов: брифинг → спецификация → план → сборка субагентами → ревью → слепая приёмка → итог; режимы `full` / `semi` / `interview` / `manual` |
| Дашборд | **один дашборд на один прогон**: `.autopilot/dashboard.html` — цвет шапки (идёт / ждёт вас / готово / провал), восемь этапов, тикеты полосками, «Ваши слова» (требования), проверки G1–G4, лента событий |
| Память между прогонами | `.autopilot/PROGRESS.md` (что осталось и о чём договорились), `carried.md`, реестр прогонов в `.autopilot/README.md`, `AGENTS.md`/`CLAUDE.md` проекта |
| Большой проект | план больше ~36 тыс. строк кода «не разрешён — разбить на два прогона»; **следующий прогон владелец запускает руками** (`/autopilot`) |
| Модели субагентов | два класса тикетов: «сильная» — модель сессии, «обычная» — более дешёвая (в Claude Code `model: "sonnet"`); ревьюеры — на сильной. Конкретные модели и усилие по ролям не задаются, привязки к Codex нет |
| Контроль «готово» | `ap.py finish` (с 2.2.3) отказывает при красных гейтах G1–G3, несданных или некоммиченных тикетах; сдача «как есть» — только со словами владельца (`--by-user`) |
| Приложения | Claude Code, Cursor, Codex и ещё 70+ агентов через `npx skills` |
| Установка и обновление | `npx skills add nick-vels/skills --skill autopilot -g -y -a <агент>` (нужен Node.js); при старте прогона навык сам сообщает, что вышла новая версия |

## Что добавляет kit

| Добавлено | Чего не было в оригинале | Где в репозитории |
|---|---|---|
| **Оркестратор программы `/autopilot-program`** | оригинал делает один прогон, следующий запускаете вы. Оркестратор разбивает проект на этапы, один раз в начале задаёт вопросы всех этапов (с рекомендованным ответом), запускает каждый этап новой сессией, передаёт вопросы этапа вам и ответы обратно, проверяет сдачу (гейт, слепая приёмка, коммит, «Следующий шаг») и запускает следующий | `kit/program.py`, навык `autopilot-program` |
| **Единый дашборд программы** | у оригинала только дашборд одного прогона. Дашборд программы показывает **все этапы сразу**: трек этапов, процент всей программы, оценку времени, следующий этап; под ним плашка **«Внутри этапа»** — восемь фаз Autopilot текущего прогона со временем, тикеты и тесты; вопрос, который ждёт вас, решения и допущения; ссылка на дашборд самого прогона (оригинальный). Страница обновляется сама | `kit/program_page.html`, `program.py page / serve` |
| **Пульт всех программ** `python -m kit dashboard` | уровень выше: все проекты на машине, что требует внимания, версия ядра против GitHub, автоматика, задачи владельца | `kit/dashboard.py`, `kit/dashboard_page.html` |
| **Роли с моделями и усилием** | оригинал различает «сильную» и «обычную» модель; kit задаёт модель **и усилие** четырём ролям (исполнитель, два ревьюера, финальный ревьюер) из вашего профиля и для каждого приложения свои имена моделей | `kit/profile.py`, `kit/render.py`, `kit/data/models.json`, навыки `autopilot-roles`, `autopilot-setup` |
| **Гейт качества** | хук Stop: «готово» не принимается, пока проходят не все тесты проекта; защита от удаления и пропуска тестов, один повтор нестабильных, журнал | `kit/gate.py`, `.autopilot-kit/project.toml` проекта |
| **Лимиты подписки** | паузы перед исчерпанием 5-часового и недельного лимита, продолжение после сброса | `program.py limits`, навык §5a |
| **Сторож программ** | будит прерванный этап (перезагрузка, закрытие приложения, падение процесса), следит за долгой работой вне чата | `program.py watch`, задача приложения |
| **Настройка проекта** | `/autopilot-init` и шаблоны: гейт, правила, разрешения, `AGENTS.md`/`CLAUDE.md`, хуки | `templates/`, навык `autopilot-init` |
| **Правила владельца** | «в этом прогоне документы, кода не будет»; раздел «Следующий шаг» с готовой командой в отчёте | навык `autopilot-roles` (§8–§9) |
| **Безопасное обновление ядра** | новая версия оригинала сначала проверяется на «швах» (файлы, заголовки, якоря, настоящий `ap.py` глазами `program.py` и `gate.py`) в песочнице и ставится только при зелёных | `kit/seams.py`, `kit trial`, `kit check-update`, `kit update` |
| **Установщик и диагностика** | `install`, `update`, `status`, `doctor`, `uninstall`, `profile set`, `project init`, `relocate` | `kit/` (Python, только стандартная библиотека, без Node.js) |

### Три уровня дашбордов

| Уровень | Что показывает | Чей |
|---|---|---|
| **Прогон** (`.autopilot/dashboard.html`) | один прогон Autopilot: этапы, тикеты, «Ваши слова», G1–G4, лента | оригинал |
| **Программа** (`.autopilot/program.html`) | все этапы программы и состояние внутри текущего этапа, вопросы к вам, решения, оценка времени | kit |
| **Пульт** (`python -m kit dashboard`, `127.0.0.1:8699`) | все программы всех проектов на машине | kit |

Дашборд прогона kit не заменяет и не меняет: программа берёт из него данные (`.autopilot/state.js`) и даёт ссылку.

## Что не меняется

| Что | Как это гарантируется |
|---|---|
| Файлы `autopilot` (`SKILL.md`, `phases/*`, `prompts/*`, `tools/ap.py`) | `python -m kit status` сверяет хеши файлов в `~/.claude/skills/autopilot` и `~/.agents/skills/autopilot` с `~/.autopilot-kit/upstream.lock.json`; правка вручную даёт `LOCAL_CHANGES`, kit отказывается перезаписывать |
| Копия в репозитории | `vendor/autopilot` совпадает с манифестом `vendor/UPSTREAM.json` (тест это проверяет) и с закреплением `kit/data/upstream.pin`; правка вручную — ошибка установки |
| Версия | закреплена в `kit/data/upstream.pin`; обновление (`kit update`) — только после проверки швов, и тогда же обновляется копия в `vendor/` |
| Интеграция | kit только **читает** то, что пишет оригинал (`.autopilot/state.js`, `PROGRESS.md`, git, итог `ap.py`), и вызывает его команды; ничего не переопределяет |

Единственный производный файл — копия `autopilot-stage` (генерируется при `install`/`update`, маркер `.autopilot-kit-generated`).
От оригинала она отличается **только заголовком `SKILL.md`**: другое `name` и `description`, нет флага `disable-model-invocation: true`
(сессия этапа вызывает навык сама, а оригинал запускается только вашей рукой). Остальные файлы идентичны.

**Известный зазор с версией 2.2.3:** оригинал теперь умеет сдавать прогон «как есть» со словами владельца (`landedWith`), а
`program.py` этого признака ещё не учитывает: при красных гейтах он покажет такой этап проваленным.

## Отличия по приводам

| Тема | Оригинал | Привод `claude` (Claude, подписка) | Привод `codex` (Codex) | Привод `claude-gate` (Claude Desktop + гейтвей) |
|---|---|---|---|---|
| Установка | `npx skills add` (Node.js) | `python -m kit install` → `~/.claude/skills` | `python -m kit install` → `~/.agents/skills` | как `claude` |
| Модели ролей | «сильная» / «обычная» без привязки к тарифу | файлы агентов `~/.claude/agents/autopilot-*.md`: `opus` / `sonnet` / `haiku`, пресеты `quality`, `economy` | поля `model` и `reasoning_effort` в `spawn_agent` из `resolved.json`: `gpt-6-astra` / `gpt-6.1-sol` / `gpt-6-luna` | те же псевдонимы, гейтвей отображает их в свои модели; пресет `desktop-gate` (исполнитель на сильной) |
| Гейт «готово» | `ap.py finish` проверяет G1–G3 | + хук Stop `.claude/settings.json` → `gate.py --hook claude-stop` | + хук Stop `.codex/hooks.json` → `gate.py --hook codex-stop` и правило в `AGENTS.md` | как `claude`, путь хука `$HOME/.autopilot-kit/bin/gate.py` |
| Программа прогонов | нет | новая сессия приложения на этап + копия `autopilot-stage` | фоновый `codex exec` (`program.py codex-run`, `codex-status`, `codex-answer`) | как `claude` |
| Лимиты | нет | `get_usage`: паузы, продолжение после сброса | `rate_limits` из `~/.codex/sessions` | не применяются (`not_applicable`); сторож и `job set` |
| Дашборд программы | — | панель рядом с чатом | ссылка в сообщениях оркестратора | панель, с заменами инструментов билда |
| Уведомления владельцу | — | `PushNotification` | сообщения чата | `mcp__ccd_turn__wrap_up` (нет `PushNotification`) |
| Проверка обновлений ядра | при старте прогона | задача приложения по понедельникам (D42) | вручную: `kit check-update` | задача приложения, если заведена в профиле гейтвея |
| Определение привода | — | `CLAUDECODE` | `CODEX_THREAD_ID` | `CLAUDE_CODE_ENTRYPOINT=claude-desktop-3p` или `drive = "…"` в профиле |
| Зрелость | — | работает | написано и покрыто тестами, живая проверка не пройдена (T15.0) | первый срез проверен 07.11.2026, перепроверка после D49 |

## Как посмотреть разницу самому

Файлы оригинала не отличаются, поэтому «diff» против них пуст, а добавленное — это содержимое этого репозитория. Проверка:

```powershell
python -m kit status          # хеши установленного оригинала совпадают с lock → файлы автора не тронуты
python -m kit check-update    # есть ли у автора новая версия, и что в ней изменилось
python -m kit trial           # как новая версия сработает с надстройкой (прод не меняется)
```

Сравнить копию этапа с оригиналом (должен отличаться только заголовок `SKILL.md`):

```powershell
diff -r ~/.claude/skills/autopilot ~/.claude/skills/autopilot-stage
```

Что менялось у автора между версиями — [CHANGELOG оригинала](https://github.com/nick-vels/skills/blob/main/CHANGELOG.md).

## Правило обновления этого файла

Файл правится при каждом обновлении ядра (`kit update`), при появлении нового привода и при новой возможности kit
(строка в [PARITY.md](PARITY.md) и здесь). Номер закреплённой версии и дата — вверху.

# Claude Code, Codex и Claude Desktop Gate: соответствие возможностей

> Оригинальный Autopilot — [nick-vels/skills](https://github.com/nick-vels/skills) (MIT, © Nick Vels): kit его не меняет и не содержит. Отличия — [DIFF_FROM_UPSTREAM.md](DIFF_FROM_UPSTREAM.md), приводы — [DRIVES.md](DRIVES.md).

Решение D24: одно ядро (`program.py`, `program.json`, план, дашборд, решения по лимитам, проверка сдачи), три привода (D48 добавил Claude Desktop Gate — таблица ниже). Каждая новая
возможность kit добавляется сюда строкой сразу для обоих приложений. Статус: **=** — одинаково; **≈** — то же для владельца, другой
механизм; **спайк** — сделано в коде, ждёт проверки на живом Codex (пункт спайка T15.0); **план** — механизм выбран, ещё не сделан; **нет** — недоступно, с причиной.

## Привод «Claude Desktop Gate» (D48)

Третье окружение: Claude Desktop 3p с гейтвеем организации (не подписка Anthropic). То же приложение и те же
инструменты, что в Claude Code, поэтому отличия — не «возможность есть/нет», а маркеры, модели и дрейф набора
инструментов билда. Живая проверка 07.11.2026 (машина B, профиль Claude-3p).

| Возможность | Claude Code (подписка Anthropic) | Claude Desktop Gate (гейтвей) | Статус |
|---|---|---|---|
| Host-маркер привода | `last_host` / `gate_log` / `orchestratorMachine`: `claude` | то же: `claude-gate` (признак `CLAUDE_CODE_ENTRYPOINT=claude-desktop-3p`; фиксация владельца `drive` в profile/project; авторитетно — `plan.status` из get_usage, D49); профиль приложения отличает сторожа и сессии | = |
| Модели и усилие ролей | файлы агентов, псевдонимы opus/sonnet/haiku, пресет `quality` | тот же механизм: блок вендора `claude-gate` (псевдонимы, гейтвей отображает их в qwen3.8-max/flash, qwen3.6-flash), пресет `desktop-gate` — исполнитель на сильной модели | ≈ |

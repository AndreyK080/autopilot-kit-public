# Руководство по использованию

> Подробности, которых нет на первой странице: настройка ролей, запуск проекта, оркестратор программ, обновление ядра, смена приложения, зависший гейт. Обзор — в [README](../README.md); приводы — в [DRIVES.md](DRIVES.md).

## Настройка ролей: `/autopilot-setup`

В Claude Code или Codex напишите `/autopilot-setup`. Мастер спросит тариф, предложит пресет (`economy` для Pro/Plus,
`quality` для остальных), покажет таблицу «роль → модель → усилие», внесёт ваши правки и запишет профиль. Без мастера:

```powershell
python -m kit profile set --preset economy --role executor=balanced:medium
python -m kit profile set --preset quality --dry-run     # только показать
```

Модель главного чата выбираете вы в приложении (рекомендуется сильная) — kit её не меняет.

## Новый проект

Если проект строится программой из нескольких прогонов, достаточно одной команды: **`/autopilot-program`** в чате, открытом в папке
проекта. Если папка не настроена (нет `.autopilot-kit/project.toml`), оркестратор сам делает то же, что `/autopilot-init` (D39), и идёт
дальше. Отдельный `/autopilot-init` нужен для одиночных запусков `/autopilot`.

Самый простой путь для одиночного запуска: откройте приложение в папке проекта (с документами внутри), выполните **`/autopilot-init`** и
следуйте отчёту. Навык сам прочитает документы и файлы, определит стек, поставит файлы kit (гейт, правила,
разрешения) и впишет команды проверки в `.autopilot-kit/project.toml`. Шаблон выбирать не нужно. Затем — новый чат в той же
папке, доверие к папке, `/autopilot-roles` и `/autopilot full: <задача>`.

Ручной путь (без навыка):

```powershell
python -m kit project init --template python-cli --path D:\Projects\my-app
```

Шаблоны: `generic` (нейтральный, его ставит `/autopilot-init`), `python-cli`, `small-web`. Существующие файлы не перезаписываются: шаблон кладётся рядом как `*.kit-new`;
`.claude/settings.json` сливается с вашим (копия прежнего — `settings.json.bak-*`).
**Всегда указывайте `--path`**: команда запускается из папки kit, и без `--path` шаблон ляжет в саму папку kit.

Гейт запускает команды из `.autopilot-kit/project.toml` тем `python`, который найден в PATH. Если у проекта свой
`.venv` с зависимостями, впишите его python: `commands = [".venv\\Scripts\\python -m pytest -q"]`.

Дальше:
1. Откройте приложение **именно в папке проекта** (не в родительской). В Claude Code примите доверие к папке — без него
   хук гейта не работает.
2. Первым сообщением: `/autopilot-roles` (в Codex: `Используй навык autopilot-roles`).
3. Вторым: `/autopilot full: <что построить>`.

Продолжение в новом чате (после перерыва или если чат закрыт) — так же: сначала `/autopilot-roles`, потом `/autopilot`.
Autopilot сам найдёт незаконченный прогон в `.autopilot/`.

## Прогон, который пишет документы, а не код

Задача Autopilot может просить не продукт, а документы: план, спецификацию, анализ («ожидаемый результат — не код»,
"planning artifacts"). Такой прогон проходит те же этапы, и без предупреждения этап «Разработка» на дашборде и коммит
«Autopilot: сборка сдана» выглядят как готовый продукт. Поэтому навык `autopilot-roles` (§8) требует от Autopilot:

- решить в начале прогона, что он даёт: код продукта или только документы; сомнение — вопрос одной строкой;
- для прогона с документами первой строкой вступления сказать: «В этом прогоне пишутся документы, код продукта не
  появится; разработка кода — следующим прогоном»;
- на дашборде: заголовок «Документы: …», пометки этапов «Пишутся документы, код продукта не пишется»;
- первой строкой отчёта: «Готовы документы, не продукт. Есть: … Кода продукта нет — пользоваться пока нечем.
  Следующий шаг: …»; то же — в итоге на дашборде, в `.autopilot/PROGRESS.md` и в теле финального коммита.

Само название этапа «Разработка» на шкале дашборда задано в оригинальном Autopilot и kit его не меняет (D5); пометка
и заголовок говорят, что на этом этапе пишутся документы. Правило действует после `python -m kit install` и в новом чате.

## Проект в несколько прогонов: следующий шаг

Если проект собирается в несколько прогонов (в плане этапы или milestones, объём больше одного прогона, часть работы
оставлена следующему этапу), навык `autopilot-roles` (§9) требует закончить итоговый отчёт разделом
«Следующий шаг»:

- готовая к вставке команда в отдельном блоке — `/autopilot-roles`, затем `/autopilot <режим>: <задание следующего
  этапа со ссылкой на план>`; её отправляют в новом чате в папке проекта;
- «Что нужно от тебя до запуска» — решения и данные (ID вопросов владельцу, аккаунты, доступы, файлы) и что будет без
  них: остановка на брифинге или допущение.

Тот же раздел пишется в `.autopilot/PROGRESS.md`, чтобы следующая сессия нашла команду без отчёта.

## Программа из нескольких прогонов: `/autopilot-program`

Чтобы не запускать этапы вручную, откройте чат приложения (Claude Desktop/Code или Codex) **в папке проекта** и напишите
`/autopilot-program` (в Codex — `$autopilot-program`) с целью или файлом плана. Оркестратор:

1. разбивает работу на этапы по плану (нет плана — первым этапом пишет его);
2. **один раз в начале** задаёт вопросы всех видимых этапов — деньги, аккаунты, вендоры, лицензии, данные,
   политики — с рекомендуемым ответом у каждого («по рекомендациям» принимает все);
3. запускает каждый этап **новой сессией** и сам вызывает в ней Autopilot;
4. когда этап спрашивает, показывает вам один вопрос и передаёт ответ обратно; проверяет сдачу (гейт, слепая
   приёмка, коммит сдачи, «Следующий шаг») и запускает следующий этап;
5. в конце выдаёт отчёт программы: что сдано, что осталось, ваши решения и допущения за вас.

**Где смотреть ход проекта.** Оркестратор называет свой чат «Оркестратор · <проект>» — это главная точка: туда приходят
все вопросы. Справа от него, в панели приложения, открыт **дашборд программы** (`.autopilot/program.html`, в стиле дашборда
прогона): сверху плашка всей программы (трек этапов, процент, оценка времени, следующий этап), под ней плашка «Внутри этапа» — восемь фаз Autopilot текущего прогона с временем, тикеты и тесты; ниже вопрос, который ждёт вас,
оценка оставшегося времени, решения и допущения, ссылка на дашборд текущего прогона. Страница обновляется сама; её
отдаёт фоновый сервер, который `program.py` сам поднимает и проверяет на каждом шаге — даже если панель закрылась или компьютер
перезагрузился. Каждое сообщение оркестратора начинается строкой трека (`M1 ✓ → M2 ● Разработка · тикеты 5/12 · 53% → M3 ○ · программа 38%`)
и строкой ссылок «Дашборд: программа · текущий прогон» — открыть можно в один клик. Слово «дашборд» в чате оркестратора открывает страницу снова;
боковую панель браузера показывает и прячет `Ctrl+Shift+B`.

Задав вам вопрос или сдав этап, чат этапа сам пишет оркестратору и присылает уведомление. Если оркестратор долго молчит, а этап
сдан, напишите ему «продолжай» — приложение перестаёт будить чат сам после длинной серии автоматических пробуждений.

**Документация на входе.** Документы могут быть любыми: цель в строку, подробный план, пачка документов из другого чата.
Оркестратор приводит их к **плану программы** `.autopilot/PROGRAM-PLAN.md` единого вида (шаблон: `python ~/.autopilot-kit/bin/program.py
plan-template`), ваши документы не меняет. В плане — брифы этапов, а не тикеты: рамки «входит / не входит», проверяемые критерии,
зависимости, что этап передаёт дальше, размер (не больше одного прогона, лучше T1–T2) и ссылки на детальные документы. Тикеты под
исполнителя пишет сам Autopilot внутри прогона. Нет нарезки на этапы — первым этапом `P0` пишется план. Шаблон можно отдать
любому чату, который пишет вам документацию. Если прогон отложил часть этапа, оркестратор запускает продолжение того же этапа
(до трёх частей), а не следующий этап.

**Лимиты подписки.** Оркестратор следит за 5-часовым и недельным лимитом (процент и время сброса берёт у приложения).
Новый этап не начинается при 5-часовом ≥ 85% или недельном ≥ 90%: программа встаёт на паузу до сброса, на дашборде —
фиолетовая плашка «Пауза до ЧЧ:ММ», вам — уведомление. Во время этапа при 5-часовом ≥ 80% оркестратор заранее ставит разовую
задачу приложения на время сброса + 2 минуты: она будит чат этапа, и программа идёт дальше сама. Платное продолжение
(extra usage) не включается. Задачи работают, пока открыто приложение; компьютер не должен спать.

Вас зовут только при вопросе, на который нет ответа, при провале этапа и перед необратимым действием (push,
оплата, публикация, удаление). Состояние — `.autopilot/program.json` и `.autopilot/PROGRAM.md`: после перезапуска
или смены чата снова напишите `/autopilot-program`, оркестратор продолжит с места остановки. За прерванным этапом
следит сторож программ (задача приложения, каждые 15 минут): после перезагрузки машины будит сразу; после
перезапуска приложения — сразу, если с его последнего прохода прошло больше двух интервалов (30 минут, T21.16);
иначе — когда прогон молчит час (15 минут между этапами).

- Чат оркестратора лучше держать в режиме разрешений **auto**: сессии этапов получают тот же режим, иначе
  встают на запросах разрешений.
- Компьютер не должен засыпать: оркестратор просит не уходить в сон, но закрытая крышка всё равно усыпит
  машину — тогда продолжите `/autopilot-program`.
- Сессия этапа запускает Autopilot через копию `autopilot-stage` (её ставит `install`): оригинальный
  `/autopilot` запускается только вашей рукой. Копию не вызывайте сами — она только для этапов.
- **Codex** (D24): `/autopilot-program` (в Codex — `$autopilot-program`) запускает этапы фоновым `codex exec`
  (`program.py codex-run`), следит за ними `codex-status` и отвечает `codex-answer`; пробуждается задачей в своём чате.
  Дашборд — ссылкой в браузере. Живая проверка привода (спайк T15.0) ещё не пройдена.

## Обновление Autopilot

Оригинальный Autopilot — чужой код: kit его не меняет и подстраивается под новые версии сам. Порядок такой: прод (ваш
домашний каталог) → проверка в dev → установка в прод только после вашего «да».

```powershell
python -m kit dashboard       # пульт всех программ: что требует внимания, этапы, гейт, версия ядра
python -m kit check-update    # есть ли новая версия Autopilot (сдвиг HEAD из-за других навыков автора не в счёт)
python -m kit trial           # поставить новую версию в dev-песочницу ~/.autopilot-kit/trial/home и проверить швы
python -m kit update          # показать изменения, проверить швы, спросить y/N, поставить в прод
```

- **Швы** — всё, на что опираются надстройки kit: файлы ядра, заголовок для копии `autopilot-stage`, тексты-якоря и
  поведение настоящего `ap.py` новой версии во временном проекте (ожидание владельца, сдача), прочитанное нашими
  `program.py` и `gate.py`. Отчёт `trial` — `~/.autopilot-kit/trial/report.md`.
- `update` не ставит версию с красными швами даже с `--yes`: сначала подстраиваются надстройки.
- **Каждый понедельник в 10:07** задача приложения «Autopilot: автообновление» (D42) проверяет новую версию, прогоняет швы в dev и,
  если они зелёные и ни один этап ни одной программы не идёт, сама ставит версию и запускает `doctor`; иначе присылает
  уведомление с причиной и повторяет в следующий понедельник. Красные швы не ставятся никогда. Задача работает, пока открыто
  приложение. Изменить или отключить — раздел «Scheduled» в боковой панели. В приводе Codex такой задачи нет: запускайте
  `python -m kit check-update` вручную.
- Если вы правили файлы Autopilot вручную, `update` и `install` откажутся их перезаписывать (`LOCAL_CHANGES`) и покажут список.

## Смена приложения (Claude Code ↔ Codex)

Проект ведётся в одном приложении за раз. Чтобы продолжить в другом, откройте проект там, повторите `/autopilot-roles`.
Навык заметит смену приложения (`.autopilot-kit/last_host`) и создаст ревьюеров заново. В Codex шаблоны кладут `.codex/hooks.json` с хуком Stop (`gate.py --hook codex-stop`, владелец один раз подтверждает его в `/hooks`);
правило в `AGENTS.md` остаётся запасным. Хук в живом Codex ещё не проверен (спайк C7).

Проектный `.autopilot-kit/profile.toml` (правки ролей для одного проекта) действует только в Codex. В Claude Code модели
ролей берутся из глобального профиля: меняйте его через `/autopilot-setup`.

## Привод «Claude Desktop Gate» (D48)

Claude Desktop 3p с гейтвеем организации (в `~/.claude/settings.json` заданы `ANTHROPIC_BASE_URL` и
`ANTHROPIC_AUTH_TOKEN`; признак окружения — `CLAUDE_CODE_ENTRYPOINT=claude-desktop-3p`) поддерживается как отдельный
привод: тот же kit, host-маркер `claude-gate` в `last_host`, журнале гейта и идентичности оркестратора. Если признак
окружения ненадёжен, привод фиксируется явно: `python -m kit profile set --drive claude-gate` (или `drive = "…"` в
`.autopilot-kit/project.toml` проекта), а оркестратор программ подтверждает его авторитетно по ответу `get_usage`
(`plan.status: ok` → подписка, `not_applicable` → гейтвей; D49). Ключ `drive` — **верхнеуровневый**: записанный после
`[gate]`/`[roles.…]` он попадает в таблицу и игнорируется (`kit doctor` предупреждает). Отличия:

- профиль: `/autopilot-setup` предложит пресет `desktop-gate` — у гейтвея нет средней модели (псевдоним sonnet даёт
  flash-модель), поэтому исполнитель работает на сильной;
- лимиты подписки не применяются (`get_usage` → `plan.status: not_applicable`): пауз и задач продолжения по лимитам
  нет, за остановками следят сторож программ и `program.py job set`;
- задачи приложения и сессии живут в профиле приложения: сторож регистрируется в каждом профиле отдельно, а
  `program.py watch` не трогает программы, которые ведёт оркестратор другого профиля (`foreign: true`);
- хук Stop в шаблонах проекта пишется с машинно-независимым путём `$HOME/.autopilot-kit/bin/gate.py` (оболочка хуков
  на Windows — Git Bash, запасная PowerShell; обе раскрывают `$HOME`): проекты на общем диске нескольких машин не
  требуют `kit relocate` — он бы переписал пути под одну машину и сломал остальные.

`python -m kit doctor` распознаёт окружение привода (в том числе по `env` в `~/.claude/settings.json`): гейтвей — OK,
а `ANTHROPIC_API_KEY`/`OPENAI_API_KEY` по-прежнему FAIL (D3: оплата по API запрещена).

## Если гейт зациклился

В Claude Code гейт блокирует остановку при красных тестах и после второго подряд провала пропускает её, печатая
«ГЕЙТ НЕ ПРОЙДЕН». Остановку он не блокирует, когда Autopilot ждёт вашего ответа (вопросы брифинга, согласование
спецификации или плана, «да/нет» перед необратимым действием) и когда тестов в проекте ещё нет.
Что делать:
1. Запустите гейт руками и посмотрите вывод: `python "%USERPROFILE%\.autopilot-kit\bin\gate.py"` из папки проекта.
2. Почините тесты или поправьте команды в `.autopilot-kit/project.toml`.
3. Сбросьте счётчик: удалите `.autopilot-kit/gate_state.json`.
4. Если нужно срочно отключить: уберите блок `hooks` из `.claude/settings.json` проекта.

Подробнее о командах — в [docs/OPERATIONS.md](OPERATIONS.md). Результаты живой приёмки — в
[docs/ACCEPTANCE.md](ACCEPTANCE.md).
